# Running Carrot-Transform with Docker

Carrot-Transform is available as a Docker container image, which makes it easy to run without installing Python dependencies locally. The image has the `carrot-transform` command ready to run, and includes test data, so you can get started quickly by only mounting an output directory.

<Steps>

### Pull the Container Image

The container image is published to GitHub Container Registry. Pull it with:

```bash copy
docker pull ghcr.io/health-informatics-uon/carrot/transform:edge
```

The following tags are published:

| Tag | Description |
| --- | --- |
| `edge` | The latest commit on the `main` branch - potentially unstable |
| `<major>.<minor>.<patch>` (e.g. `1.2.3`) | A specific release |
| `<major>.<minor>` / `<major>` (e.g. `1.2` / `1`) | The most recent release within that minor or major version |
| `latest` | The most recent stable release |

<Callout type="warning">
  **Version Pinning**: We recommend that you pin to a specific version of Transform for production use to ensure consistent behavior and avoid unexpected changes from updates.
</Callout>

For a specific version, check available tags at the [container registry](https://github.com/Health-Informatics-UoN/carrot-transform/pkgs/container/carrot%2Ftransform).

### Understand the Docker Command

Every example on this page follows the same pattern:

```bash
docker run [docker options] ghcr.io/health-informatics-uon/carrot/transform:edge \
  carrot-transform [command] [options]
```

Everything after the image name is the `carrot-transform` command, exactly as you would run it after [installing it locally](/transform/quickstart). Running the image with no command prints the `carrot-transform` help text.

The Docker flags used are:

- **`--rm`**: Removes the container once it exits, so stopped containers don't build up
- **`-v`**: Mounts a volume (directory) from your host machine into the container
  - Format: `-v <host-path>:<container-path>`
  - This allows the container to read from and write to files on your machine
- **`$(pwd)`**: Shell command that expands to your current working directory
  - Example: If you're in `/Users/John-Doe/Documents/carrot`, then `$(pwd)/output` becomes `/Users/John-Doe/Documents/carrot/output`

In the examples below, `-v $(pwd)/output:/output` mounts a local `output` directory (created in your current folder) to `/output` inside the container, and `--output /output` tells Transform to write there, allowing you to access the transformed files on your machine.

The container includes test data and example mapping rules, which can be referenced with the `@carrot` alias (see [@carrot Alias](/transform/quickstart#carrot-alias)), so you can run Transform immediately without providing input files.

### Running V1 JSON Mapping Rules with Docker

The following example shows how to run the V1 transformation process using Docker. V1 process of Transform uses the `run v1` command and takes V1 JSON mapping rules from Carrot Mapper.

Run V1 with a volume mount so you can access the output files on your host machine:

```bash copy
docker run --rm -v $(pwd)/output:/output \
  ghcr.io/health-informatics-uon/carrot/transform:edge \
  carrot-transform run v1 \
    --inputs @carrot/examples/test/inputs \
    --rules-file @carrot/examples/test/rules/v1.json \
    --person Demographics \
    --output /output
```

### Using Your Own Files

To transform your own data, mount the directories holding your input files and mapping rules into the container, and use the container paths in the command. For example, with your CSV files in `./data` and your rules file at `./rules/rules.json`:

```bash copy
docker run --rm \
  -v $(pwd)/data:/data \
  -v $(pwd)/rules:/rules \
  -v $(pwd)/output:/output \
  ghcr.io/health-informatics-uon/carrot/transform:edge \
  carrot-transform run v2 \
    --inputs /data \
    --rules-file /rules/rules.json \
    --person Demographics \
    --output /output
```

Replace `run v2` with `run v1` if you have V1 mapping rules, and `Demographics` with the name of your person file. See the [Quickstart Guide](/transform/quickstart#arguments) for all the available arguments.

<Callout type="info">
  The container currently runs as `root`, so on Linux the files written to your mounted output directory will be owned by `root`.
</Callout>

### Clean up

```bash copy
docker ps -a
```

This will list all containers. The examples above use `--rm`, so their containers are removed automatically. To remove any other container, use:

```bash copy
docker rm -f <container_id>
```

To remove the images, run:

```bash copy
docker rmi -f ghcr.io/health-informatics-uon/carrot/transform:edge
```
